# V4.5.1 Generation Authority and Sandbox Report

## Standard generation authority

- Standard UI, manual-seed UI, Sandbox base rolls, and distribution tests enter through the modular generator facade.
- The facade currently delegates to the inline compatibility adapter. That adapter remains an explicitly recorded retirement target; it is not presented as a fully modular generator.
- Battle calculations remain an inline compatibility implementation.
- Standard generation has no persistent pity state. Legacy `op-mentor-pity` and `op-weapon-pity` storage keys are not read or written by any generation roll.
- Save-character ID allocation remains browser-local metadata and is excluded from gameplay determinism comparisons.

## Determinism contamination coverage

The Developer Test panel checks one fixed seed against:

1. 100 unrelated ordinary generations;
2. legacy pity storage values of 0/0, 12/22, and 99/99;
3. direct invocation through the modular facade and inline adapter.

The compared snapshot excludes ID, generated timestamp, display name, and Sandbox metadata. Those fields are not gameplay inputs. A fresh load with arbitrary legacy pity values is equivalent because the standard rolls contain no persistent-pity reads.

Verified in this pass: catalog validation 0 errors; fixed-seed snapshot parity passed; 10,000 Standard generations completed with 0 exceptions; contamination test passed; Guided target-tier and Unrestricted nine-blade/Asura construction both produced reproducible builds.

## Sandbox construction modes

| Mode | Authority | Limits | Reporting |
| --- | --- | --- | --- |
| Standard | Seeded weighted generator | All normal gates | Included in distribution statistics |
| Guided Sandbox | Direct build plus seeded unspecified values | Normal caps and lore-oriented prerequisites | `GUIDED SANDBOX` badge and automatic-adjustment list |
| Unrestricted Creator | Direct build plus seeded unspecified values | Allows overcap presets, replicas, nine physical weapons, forced Asura, and custom display tiers | `UNRESTRICTED SANDBOX` badge and bypass report |

Sandbox builds store `generationMode`, `generationProvenance`, `baseSeed`, and a deterministic `buildId`. `buildId` hashes the versioned configuration; the existing 32-bit seed remains the source of all unspecified random fields.

## Canon boundary

Asura remains canon-inspired as three physical swords plus a Nine Sword advanced manifestation. A nine-physical-blade selection is reported as a Sandbox Nine-Blade loadout and never misrepresented as canon Asura.

## Explicit exclusions

Nonstandard Sandbox builds may be saved, exported, and used in battles, but are excluded by construction from normal distribution generation, rarity claims, and standard balance samples. The distribution test only invokes the no-options Standard path.
